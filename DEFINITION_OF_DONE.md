# Definition of Done

## Current Objective

The current objective of Sanctuary is to support Patrik's preparation for entering a professional software development career.

This stage focuses on developing and strengthening his technical skills, establishing professional engineering practices, and developing a set of substantial projects that demonstrate his ability to work across the modern web development stack.

When this objective is achieved, the Definition of Done may be revised to reflect the next stage of Sanctuary's development.

## Job Search Ready

This stage is considered complete when Sanctuary and its associated projects provide a strong and representative demonstration of Patrik's current technical abilities and engineering practices.

### 1. Engineering Foundation

Sanctuary itself must demonstrate the ability to establish and maintain a professional monorepository.

The repository should include:

* a clearly defined and maintainable monorepo structure,
* shared packages used by multiple applications where appropriate,
* consistent development tooling,
* TypeScript configuration,
* code quality tooling,
* testing infrastructure,
* CI/CD,
* appropriate documentation,
* documented significant architectural decisions,
* a clear and reproducible development workflow.

The architecture must remain intentionally simple and must not contain technologies or abstractions without a concrete purpose.

### 2. Portfolio Application

A dedicated portfolio application must demonstrate strong frontend development skills.

The portfolio should demonstrate, where appropriate:

* React,
* TypeScript,
* modern React practices,
* responsive design,
* accessibility,
* internationalization,
* client-side application architecture,
* state management where justified,
* performance considerations,
* testing,
* production deployment.

The portfolio itself should serve as the primary public presentation of Patrik's work and should link to the relevant projects and repositories.

### 3. Reusable React Library

A reusable React library must be developed as a genuine software package rather than solely as a portfolio demonstration.

The library should demonstrate:

* reusable React components and/or utilities,
* TypeScript,
* a clear public API,
* appropriate component design,
* accessibility,
* testing,
* documentation,
* package/build configuration,
* versioning and maintainability.

The library must be consumed by multiple Sanctuary projects where technically appropriate, demonstrating that it is genuinely reusable.

### 4. Full-Stack Strategy Game

The primary full-stack application will be a browser-based strategy game designed to demonstrate end-to-end application development and the implementation of persistent game systems.

The game must remain intentionally limited in scope and must have a clearly defined MVP.

The project must use Next.js and Node.js and include a backend API.

The MVP should demonstrate, at minimum:

- user authentication,
- a persistent player profile,
- a persistent game state,
- a defined game world or map,
- resource or economic mechanics,
- meaningful player decisions,
- server-side validation of game actions,
- API communication between client and server,
- persistent database storage,
- separation between presentation, game logic and authoritative server state.

Additional mechanics may be introduced only when they provide meaningful gameplay value and remain within the defined scope of the project.

The game must be sufficiently complete to be playable rather than functioning solely as a technical demonstration.

### 5. Supporting Microprojects

Additional smaller projects and experiments may be created to demonstrate specific technical capabilities that are not sufficiently represented by the main projects.

These may include areas such as:

* JavaScript,
* TypeScript,
* SQL,
* database design,
* API design,
* performance,
* testing,
* browser capabilities,
* algorithms or data structures,
* other technically relevant subjects.

Microprojects are optional and must have a clear purpose. They must not become a substitute for completing the primary projects.

### 6. Engineering Quality

The projects must demonstrate professional development practices appropriate to their scope.

This includes:

* meaningful Git history,
* understandable commits,
* branching and integration practices,
* automated quality checks,
* automated tests where appropriate,
* reproducible builds,
* CI/CD,
* appropriate handling of configuration and secrets,
* reasonable security practices,
* clear documentation,
* maintainable code.

### 7. Public Presentation

The completed work must be publicly understandable without requiring private context.

A potential employer should be able to identify:

* what each project does,
* why it exists,
* which technologies it uses,
* how it is structured,
* what technical problems it solves,
* how it was developed,
* and where to inspect or use it.

The public presentation should demonstrate technical capability without presenting Sanctuary as a collection of tutorial exercises or technology experiments.

### 8. Completion of This Stage

The current stage may be considered complete when:

* Sanctuary provides a stable and maintainable engineering foundation,
* the portfolio application is publicly presentable,
* the reusable React library is functional and used by multiple projects,
* the strategy game is complete enough to demonstrate end-to-end development and has reached its defined MVP,
* supporting microprojects fill any remaining significant demonstrative gaps,
* the repositories and documentation present a coherent professional profile,
* and the resulting body of work is sufficient to begin actively pursuing professional software development opportunities.

This stage does not require mastery of every technology used in modern software development.

Technologies and architectural approaches must continue to be selected according to the problems being solved rather than the objective of maximizing the number of technologies represented.

## Out of Scope for This Stage

The following are intentionally not required for the current Job Search Ready stage:

* mobile application development,
* React Native,
* additional database technologies without a demonstrated need,
* GraphQL without a demonstrated need,
* unnecessarily complex distributed architectures,
* technologies introduced solely for portfolio appearance.

These may become part of a future Definition of Done after the current objective has been achieved.
